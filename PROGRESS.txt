RedstoneLab - developer notes
=============================
Minecraft 1.21.11 · Fabric Loader 0.19.5 · Fabric API 0.141.6 · Mojang mappings · JDK 25 to build, Java 21 to run
Only dependency: Fabric API. Mod Menu optional (compile-only).

CODE
  core/       plain Java: Ticks (3t/5t, 2t or 3t), PulseMeter, OrderLine, PistonOrder, TickPhase, MeterEvent
  capture/    Capture, PowerWatch: block / block-entity changes at metered blocks, tick phase
  mixin/      server hooks: tick phases, block changes, piston moves (meters follow, firing order)
  feature/    MeterFeature (meters, timeline data, tick list), PistonView + PushPreview (piston
              previews), PistorderFeature (previews for players without the client mod), PistonFires
  display/    MarkerService, FakeDisplays, LabBossBar: what players without the client mod see
  net/        payloads + handshake (protocol 14); command/, config/, server/, util/
  client/     ClientNetworking, ClientState, ClientPistons (previews client-side, any server)
  client/ui/  LabConfig (config/redstonelab.json), LabConfigScreen, KeyCombo + LabKeys (combos),
              TimelineHud, WorldMarkers (vanilla gizmos)

TESTS
  ./gradlew runGameTest                         68 server tests against the real game
  xvfb-run ./gradlew runClientGameTest          real client: keys, clicks, screenshots
  Accuracy checks that run every time:
  * 8 random circuits, every meter vs the real block every tick (~6000 checks)
  * 300 random piston setups vs the game's push calculation
  * 60 random observer-clock piston builds: every real move vs the preview from the tick before
  * client previews vs server previews for identical blocks (240 ticks)
  * client-side power check vs the game (433k checks; comparators read from their lit state)
  * firing order of 4 pistons on a clock; items in / out in the right part of the tick
  * container meters vs real comparators (double chest, blocked chest, composter, "x at y")
  * slow clock (150t / 150t), pause between two clocks, block replaced under a meter
  * client: hotkeys while another key (sprint) is held
  * real builds (ComplexCircuitTests + CircuitTruth: every meter's on / off each tick, pulse
    lengths and order line vs the recorded game): dropper pair with a QC BUD, comparator
    clock (0-tick lamp flicker), double piston extender (+ previews), torch burnout clock,
    repeater latch, hopper line
  * Minecraft Wiki circuits (WikiCircuitTests, built by WikiSchematic from the wiki's own
    {{Schematic}} text; test area 16x12x16): hopper-loop 7/7, 4-hopper loop 7/21, Etho hopper
    clock 34/2 (+ previews), subtraction 4gt 2/2 and 8gt 4/4, fader pulser 58gt, 5- and
    6-observer clocks, double observer 6gt / 4gt, piston clock D, TFF O1 / O / N, locked-
    repeater and moved-block rising edge detectors, a flying machine (meters ride along)
    Note: the wiki's "simple 4gt piston clock" runs 6gt as built here in 1.21.11.
  * hopper item sorter (wiki, 2 filters tiled: diamonds, iron; 41 + 4 sticks, "3 at 46")
    and a 2x2 sticky piston door (doorway really opens / closes, previews, meters)
  * client: slow motion keys (Left x2 = 5 tps, Right = 10, Down = 20)
  * FeatureTests: every /rlab command through the real command tree (meter add / remove /
    name / expect / clear, tool, piston landing, help, config set + bad value, group switch /
    delete / share), Meter Tool clicks, groups saved and reloaded on join, meter limit,
    permission levels, boss bars for players without the client mod
  * client: M / M again / R + M on a real block, settings save + load, broken settings file,
    first-join hint
  * 4-bit binary counter (4 chained observer TFFs, 40 / 80 / 160 / 320t, order line shows the
    ripple) and a full adder from the wiki's XOR / AND gates (all 8 inputs)

KNOWN LIMITS
  * On a fast clock a sticky piston is never still while out, so its pull is never previewed.
    Not worth guessing: on the clock test only 32 of 98 such retractions pulled (the rest drop).
  * Without the mod on the server, firing-order gaps are measured client-side (lag: off by 1).
